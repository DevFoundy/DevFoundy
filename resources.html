HTML

HTML cheat sheet

HTML cheat sheet

Element or attribute Use
<!DOCTYPE html> Request modern HTML behavior
html lang="en" Declare the page language
head / title / meta Metadata, tab title and viewport setup
header / nav / main / footer Meaningful page regions
section / article / div Named topic, independent item, neutral wrapper
h1 / h2 / h3 / p Content hierarchy and paragraphs
ul / li Unordered list and list item
a href="#about" Navigate to the unique id="about"
img src="..." alt="..." Image path and text alternative
button A native keyboard-accessible action control
class / id Reusable grouping / unique identifier
hidden / data-category Hide inactive content / store a custom value

Checklist: valid nesting, matching closing tags, one main landmark, useful text, working paths and unique IDs. Use a button for an action and a link for a destination.

HTML早見表

要素・属性 用途
<!DOCTYPE html> 現在のHTML標準でページを表示する
html lang="ja" ページの言語を日本語に指定する。英語ページでは en を使う
head / title / meta ページ情報、タブのタイトル、画面幅の設定
header / nav / main / footer ヘッダー、ナビゲーション、本文、フッターを示す
section / article / div 話題ごとの区切り、独立した記事、汎用の箱
h1 / h2 / h3 / p 見出しの階層と段落
ul / li 箇条書きと各項目
a href="#about" id="about" の場所へ移動するリンク
img src="..." alt="..." 画像の場所と代替テキスト
button キーボードでも操作できるボタン
class / id 繰り返し使う分類と、一意の識別子
hidden / data-category 内容を非表示にする属性と、独自データの保存

確認ポイント: タグが正しく入れ子になっているか、閉じタグが対応しているか、main が一つか、リンク先や画像のパスが動くか、id が重複していないかを確認しましょう。操作にはボタン、移動にはリンクを使います。

CSS

CSS cheat sheet

CSS cheat sheet

Pattern Meaning
.card / #projects / h1 Class / ID / element selector
color / background Text color / background fill
var(--accent) Read a custom property
padding / margin / gap Inner space / outer space / space between items
border / border-radius Edge / corner rounding
box-sizing: border-box Include padding and border in a declared width
display: flex Arrange direct children on a main axis
justify-content / align-items Align on main axis / cross axis
flex-wrap: wrap Allow flex items onto another line
display: grid Create a row and column layout
repeat(3, minmax(0, 1fr)) Three equally flexible Grid tracks
width: min(1100px, calc(100% - 2rem)) Bounded fluid page width
max-width: 100%; height: auto Let images shrink proportionally
@media (min-width: 640px) Apply rules at or above this viewport width
:hover / :focus-visible Pointer feedback / visible keyboard focus
transition / transform Smooth a change / visually move an element

When styling fails, check the matching selector, stylesheet path, cascade, spelling and missing braces. Inspect the element instead of randomly increasing selector specificity. The final course's only !important rule protects the native hidden attribute from layout overrides.

CSS早見表

書き方 意味
.card / #projects / h1 クラス、ID、要素を選ぶセレクター
color / background 文字色と背景色
var(--accent) CSSのカスタムプロパティを使う
padding / margin / gap 内側の余白、外側の余白、要素間のすき間
border / border-radius 枠線と角の丸み
box-sizing: border-box 指定した幅に余白と枠線を含める
display: flex 子要素を一方向に並べる
justify-content / align-items 主軸と交差軸で配置を調整する
flex-wrap: wrap 入りきらない要素を次の行へ送る
display: grid 行と列のレイアウトを作る
repeat(3, minmax(0, 1fr)) 均等に伸びる3列を作る
width: min(1100px, calc(100% - 2rem)) 画面に合わせつつ最大幅を制限する
max-width: 100%; height: auto 画像の比率を保って縮小する
@media (min-width: 640px) 画面幅が640px以上のときに適用する
:hover / :focus-visible ポインター操作とキーボード操作の状態を示す
transition / transform 変化を滑らかにする、要素を移動・変形する

CSSが効かないときは、セレクター、ファイルのパス、上書き順、スペル、波括弧を確認しましょう。むやみにセレクターを強くする前に、開発者ツールで対象の要素を調べてください。完成版の !important は、標準の hidden 属性がレイアウト指定で無効にならないようにするためだけに使います。

GIT

Git cheat sheet

Git cheat sheet

Command What it does
git --version Check that Git is installed
git init Create a repository in the current folder
git status Show staged, unstaged and untracked changes
git diff Inspect unstaged text changes
git add index.html Stage one file's current changes
git add . Stage changes under the current directory
git diff --cached Inspect the staged changes
git commit -m "Message" Save the staged snapshot locally
git log --oneline -5 Review the five latest commits
git remote -v Inspect remote repository addresses
git push -u origin main First push and upstream setup
git push Send new commits to the configured upstream
git pull --ff-only Get remote changes only if a fast-forward is possible

If pull refuses because histories diverged, stop and inspect rather than using force or discarding work. Pull is useful when the remote changed on another computer or in the web editor. It is not a substitute for committing your own local work. git status and reading the error are your first recovery tools.

Git早見表

コマンド 用途
git --version Gitがインストールされているか確認する
git init 現在のフォルダーでリポジトリを作る
git status 変更済み、ステージ済み、未追跡のファイルを確認する
git diff ステージ前の変更内容を見る
git add index.html 指定したファイルの変更をステージする
git add . 現在のフォルダー以下の変更をステージする
git diff --cached ステージした変更内容を見る
git commit -m "Message" ステージした内容をローカルに保存する
git log --oneline -5 直近5件のコミットを見る
git remote -v 接続先リポジトリのURLを確認する
git push -u origin main 初回のプッシュと追跡先の設定を行う
git push 新しいコミットを接続先へ送る
git pull --ff-only 安全に早送りできる場合だけ接続先の変更を取り込む

履歴が分かれたために git pull が失敗したら、強制操作や変更の破棄をする前に git status とエラー内容を確認しましょう。別のPCやWeb上で変更したときには git pull が役立ちますが、自分の変更をコミットする代わりにはなりません。
