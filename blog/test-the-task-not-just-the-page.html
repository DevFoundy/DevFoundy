Test the Task, Not Just the Page

A page can look finished while the useful part still needs work.

By Kenta·November 3, 2026·3 min read

A screenshot can tell you whether a page looks balanced. It can’t tell you whether someone knows what to click next.

That matters for the kinds of websites I want to build through DevFoundy. A portfolio, a small business site, or a project page needs to help someone do something. Looking good is part of that, but there’s a journey to check too.

Start with a visitor’s goal

Choose one reason someone would arrive. For a portfolio, it might be finding a relevant example and contacting its creator. For a course page, it might be opening the first lesson.

Write down the starting point and the finish. Then follow the route between them without skipping steps because you already know where everything is.

If the contact details are only in the footer, can someone find them from the project they’re reading? If a button says “Get started”, does its destination explain what actually starts?

Check the words around the action

A working link can still be confusing. “Learn more” gives very little information when several cards use it for different destinations.

Try a label that names the next step: “Open the workbook”, “View the project”, or “Email me about a website”. The visitor should have a reasonable idea of what will happen before they click.

Be clear about what exists today. If a service requires a conversation first, say that. If a resource opens directly, don’t make the link sound like a checkout.

Change the conditions

Try the same task on a narrow screen. Increase the text size. Use the keyboard to move through the links and controls.

These checks can reveal problems that are easy to miss while arranging a page on a large display:

  • A navigation link that disappears without another way to reach it
  • A heading that wraps over a button
  • A control whose keyboard focus is hard to see
  • A long title that pushes useful information out of its card

The aim is to make the main route hold up when the visitor’s setup differs from yours.

Watch where someone hesitates

If you can ask someone to try the page, give them a task rather than a tour. “Find a project you’d like to know more about and get in touch” leaves them room to show you how they interpret the site.

Resist explaining every label as they go. Notice where they pause, which link they expect to work, and whether they recognise when they’ve finished.

One attempt won’t prove the whole site is easy to use. It can still expose a very specific problem worth fixing.

Before adding another section, I want to ask whether the existing route is clear enough.

A useful final check: can a visitor finish the task without the builder standing beside them?
