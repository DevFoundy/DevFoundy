Learning to Code When You Already Have an Idea

Having an idea makes me want to start building immediately. I'm still figuring out how to balance that excitement with learning the things I need to understand.

By KentaNovember 6, 20263 min read

The Idea Usually Comes First

What interests me most about programming is what I can create with it.

I enjoy understanding how things work, but I don't usually get excited about a project because I want to use a particular programming concept.

I get excited because I can imagine something I'd like to exist.

Then I have to work out how to build it.

That can be a good reason to learn. It can also be slightly frustrating, because the idea in my head is often more developed than my ability to make it work.

My First Project Wasn't Particularly Good

My first real software project was a fitness-tracking website called KineticForm.

At the time, I barely understood how programming worked. I was still learning the fundamentals, and the website wasn't particularly good.

But I think there was something useful about having a project I actually wanted to make.

It gave all the unfamiliar concepts somewhere to belong. I wasn't only learning about software in the abstract. I was trying to create something I could open and interact with.

Of course, wanting a project to work doesn't automatically tell you how to fix it.

That's the part I'm still learning.

Getting Help and Understanding the Result

AI-assisted coding helped make software development feel accessible to me.

Being able to describe an idea and get help turning it into code made it much easier to start experimenting. I still think that's exciting.

But getting something on the screen and understanding how it works are different stages of the process.

If I want to change a feature, I need some understanding of what it's connected to. If something breaks, I need to be able to ask useful questions about it.

I don't think that means I have to understand every line immediately. That would be a fairly unrealistic expectation for someone who's still learning.

But I do want to keep closing the gap between being able to make something and being able to explain it.

A Smaller Question Is Easier to Work On

When an idea feels too complicated, I find it useful to think about what I actually need to understand next.

For example, a fitness-tracking website sounds like a whole product. Saving one workout and being able to find it again is a more specific thing to think about.

It still raises questions. What information needs to be saved? How should it be displayed? What happens if there aren't any workouts yet?

But at least those questions belong to something concrete.

That's an approach I want to keep using: let the project give me a reason to learn, then make the next question small enough that I can work on it.

I Don't Want Learning to Become a Reason to Wait Forever

There are plenty of things I don't understand yet, particularly when it comes to more advanced programming and integrations.

I could use that as a reason to keep postponing every idea until I feel ready.

But I don't think I'd ever reach a point where I felt ready for everything.

I'd rather keep experimenting while also making time to understand what I'm doing. Some projects will be rough. Some ideas will need to wait. And sometimes I'll have to go back to the basics.

I'm comfortable with that.

I don't need every project to prove that I'm already a great developer.

Sometimes, I just need it to help me become a slightly better one.
