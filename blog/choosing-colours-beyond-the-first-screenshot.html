Choosing Colours Beyond the First Screenshot

I like an appealing palette, but I'd also want to see how it behaves across the rest of an interface.

By KentaOctober 29, 20262 min read

Colour is one of the enjoyable parts of working on a design.

A small change can affect the whole mood of a page. The same layout can feel quieter, brighter, more playful, or more formal depending on the palette around it.

But a colour combination that looks good in one screenshot still needs to work in the rest of the interface.

The Smaller Text Matters

A large heading is only one part of a page.

There might also be captions, input labels, secondary buttons, and status messages. I'd want to look at those before deciding the palette is finished.

If the quieter text becomes difficult to read, making it subtle hasn't really helped the design.

The same goes for the colours of links and selected items. People need to recognise those differences while using the page.

Try the Less Attractive States Too

An empty input, a disabled button, and an error message might not be the most exciting parts to arrange in a preview.

They're still part of the product.

I'd want to see whether the colours explain those states clearly, including whether the message still makes sense without relying on colour alone.

A label or icon can give the difference another way to be understood.

I enjoy the visual side of these decisions. I just don't want to stop at the version that looks best in a single image.

A palette becomes more interesting to me when it can support the ordinary, messy variety of things that happen while someone actually uses a website.
